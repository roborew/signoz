# SigNoz Deployment (Docker Compose)

This directory is a self-contained Docker Compose project for running self-hosted
SigNoz. It was originally generated by `foundryctl` (`foundryctl cast -f ../../casting.yml`)
but is now managed directly with Docker Compose.

## Running

Always run from **this directory** (the volume mounts use relative paths):

```bash
cd /Users/robomini/01_REPOS/utilities/signoz/pours/deployment

docker compose up -d          # start / apply changes
docker compose ps             # status
docker compose logs -f signoz-signoz-0
docker compose down           # stop (named volumes / data are preserved)
docker compose pull && docker compose up -d   # update images
```

## Services

- `signoz-signoz-0` — app + UI (container port 8080)
- `ingester` (`signoz-ingester-1`) — OTLP receiver: 4317 (gRPC), 4318 (HTTP)
- `signoz-metastore-postgres-0` — Postgres metastore
- `signoz-telemetrystore-clickhouse-0-0` + `signoz-telemetrykeeper-clickhousekeeper-0` — ClickHouse telemetry store
- `signoz-telemetrystore-migrator` / `-user-scripts` — one-shot bootstrap jobs

All images are pre-built and pulled from registries — there is no Dockerfile here.

## Traefik / Cloudflare routing

This stack is fronted by Traefik (Docker provider, network `traefik-desktop`),
which is in turn reached via a Cloudflare Tunnel. Routing is done with labels
in `compose.yaml`, so **no host ports are published for HTTP** (avoids conflicts,
e.g. the earlier 8080 clash with Label Studio):

- `signoz-signoz-0` → `Host(signoz.roborew.xyz)` → container port 8080 (UI)
- `ingester` → `Host(otel.roborew.xyz)` → container port 4318 (OTLP/HTTP ingest)

Cloudflare only exposes port 443 publicly, so remote OTLP senders must use
**OTLP/HTTP** to `https://otel.roborew.xyz` (not gRPC on 4317). The Cloudflare
Tunnel public hostname for `otel.roborew.xyz` uses **No TLS Verify** on the origin.

## Important: foundryctl regeneration

The Traefik labels and network wiring in `compose.yaml` were added by hand.
Re-running `foundryctl cast` will **regenerate this file and overwrite those edits**
(reintroducing the `8080:8080` host publish and dropping the `otel.roborew.xyz`
route). Manage this stack with `docker compose` directly, and only re-cast if you
are prepared to re-apply the customizations.

## Data

Data lives in named volumes (`signoz-metastore-postgres-0-data`,
`signoz-telemetrystore-0-0-data`, `signoz-telemetrykeeper-0-data`,
`signoz-telemetrystore-user-scripts`) and survives `docker compose down`.
